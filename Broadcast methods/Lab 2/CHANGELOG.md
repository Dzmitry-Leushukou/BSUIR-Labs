# Лексический анализатор Idris 2 - Версия 2 (обновлён вывод)

## Изменения в версии 2

Переделан формат вывода программы согласно требованиям преподавателя:

### 1. **Единая таблица "CONSTANTS AND IDENTS"**

Вместо двух отдельных таблиц (идентификаторов и констант) теперь выводится одна объединённая таблица с общей нумерацией в порядке первого появления:

```
CONSTANTS AND IDENTS

ID    | Value
---   | ---
1     | Main
2     | Data
3     | Vect
4     | initialValue
5     | Int
6     | 42
...
```

**Особенности:**
- Единая нумерация для идентификаторов и констант
- Порядок: в порядке первого появления в коде
- Для идентификаторов: имя без кавычек
- Для чисел: литерал как в коде (0x1F, 1e-10, 2., и т.д.)
- Для строк: в двойных кавычках с экранированием
- Для символов: в одинарных кавычках с экранированием

### 2. **Преобразованный код**

После таблицы выводится исходный код с заменой всех идентификаторов и констант на `<IDn>`:

```
module <ID1> import <ID2> . <ID3> <ID4> : <ID5> <ID4> = <ID6> ...
```

**Особенности:**
- Все токены разделены ровно одним пробелом
- Компо́зные операторы остаются одним токеном (`, ->, =>, ::, /=, /*, и т.д.)
- Переводы строк игнорируются - вывод в одну строку
- Ключевые слова, операторы, разделители выводятся как есть

### 3. **Обработка ошибок**

Если при анализе обнаружена хотя бы одна ошибка:
- Выводятся только сообщения об ошибках
- Таблица и код не выводятся
- Формат ошибок: `Лексическая ошибка в строке N, колонка M: описание`

## Исправления и улучшения

### Исправлен парсинг чисел с экспонентой

**Было:** `1e-10` парсилось как три токена: `1`, `e`, `-10`
**Стало:** `1e-10` корректно парсится как один токен `FloatLiteral`

Изменение: Удалено условие `&& is_float` из проверки экспоненты, чтобы позволить целым числам иметь экспоненту.

### Добавлена поддержка `_` как идентификатора

**Было:** `_` (wildcard) выводил ошибку "unrecognized character"
**Стало:** `_` корректно распознаётся как идентификатор

Изменение: Добавлена проверка `|| ch == '_'` при распознавании начала идентификатора.

### Исправлено распознавание оператора `/=`

**Было:** `/=` парсилось как два токена: `/` и `=`
**Стало:** `/=` корректно распознаётся как один токен `NotEqual`

Изменение: Добавлена проверка для `'/'` на наличие следующего `'='`, аналогично `'!'`.

## Описание файлов

### Модифицированные файлы:

1. **src/symbol_table.rs**
   - Добавлена структура `TableEntry` (enum для identifiers/constants)
   - Добавлена структура `UnifiedTable` (единая таблица с методами добавления и поиска)
   - Добавлен метод `value_string_raw()` для корректного вывода с экранированием

2. **src/lexer.rs**
   - Исправлено распознавание научной нотации (1e-10)
   - Добавлена поддержка `_` как начало идентификатора
   - Исправлено распознавание оператора `/=`

3. **src/main.rs**
   - Переписан формат вывода для использования единой таблицы
   - Добавлено преобразование кода с заменой идентификаторов/констант на `<IDn>`
   - Автоматический выход с кодом 1 при ошибках (без таблицы и кода)

### Файлы без изменений:

- **src/token.rs** - Определения типов (без изменений)

## Тестовые файлы

Всё работает с тремя группами тестов:

1. **Успешный парсинг** (3 файла):
   - `test1.idr` - Базовый пример с модулем и типами
   - `test_advanced.idr` - Продвинутые функции, вложенные комментарии, научная нотация
   - `test_comprehensive.idr` - Полный тест всех операторов и конструкций

2. **Обнаружение ошибок** (4 файла):
   - `error1.idr` - Нераспознанный символ `#`
   - `error2.idr` - Незакрытая строка
   - `error3.idr` - Незакрытый многострочный комментарий
   - `error4.idr` - Пустая шестнадцатеричная константа `0x`
