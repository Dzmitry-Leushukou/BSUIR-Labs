ГОСТ 34.10 простыми словами

Разберём, как программа доказывает, что файл подписал владелец секретного ключа и что после подписания файл не меняли. Начнём с идеи, а к формулам перейдём постепенно.

1. Что такое электронная подпись

Подпись не прячет содержимое файла. Для этого нужно шифрование, а здесь задача другая: проверить автора и целостность.

Представь, что ты положил документ в прозрачный конверт и поставил на нём особую печать. Любой может прочитать документ и проверить печать, но только владелец секретного ключа может такую печать поставить.

У электронной подписи три главных участника:

Секретный ключНужен автору, чтобы создать подпись. Его нельзя раздавать.
→
Файл и его хэшХэш коротко представляет содержимое файла.
→
Подпись и открытый ключПодпись отправляют с файлом. Открытым ключом её проверяют.

Если поменять в файле хотя бы один байт, его хэш почти наверняка станет другим. Старая подпись тогда перестанет проходить проверку.

Что даёт подпись: подтверждает соответствие подписи паре ключей и показывает, что проверяемые байты совпадают с подписанными. Сама по себе она не доказывает паспортную личность человека: открытый ключ ещё нужно надёжно связать с его владельцем.

2. Два ключа и очень особая математика

Программа создаёт два связанных числа. Одно держат в секрете, второе можно показывать всем.

Закрытый ключ dСлучайное число. Им создают подпись. Его файл нужно беречь.
Открытый ключ QТочка на эллиптической кривой. Ею проверяют подпись. По ней практически невозможно восстановить d.

Открытый ключ считается из закрытого так:

Q = d · PP — заранее заданная точка кривой. Умножить точку на число значит много раз выполнить специальное сложение точек.

Обычные числа здесь не совсем подходят: вместо них используются точки эллиптической кривой. Уравнение выбранной кривой имеет вид:

y² ≡ x³ + a·x + b (mod p)Не пугайся слова «эллиптическая»: для программы это просто набор допустимых пар координат (x, y), проверяемых по формуле.

mod p означает «взять остаток после деления на p». Например, на часах после 12 снова идёт 1. В арифметике по модулю 17 после 16 снова идёт 0. Так все вычисления остаются в ограниченном диапазоне.

У программы есть две важные константы:

p — модуль координат
По нему считаются координаты точек и проверяется уравнение кривой.
q — порядок базовой точки P
По нему считаются закрытый ключ, случайное число для подписи и значения r и s. Проще: это размер циклического набора точек, который использует подпись.

В реализации выбраны параметры эллиптической кривой TC26 paramSetA. Координаты открытого ключа записываются как два 256-битных числа — x и y.

Секретность держится не на том, что формулы скрыты. Все параметры кривой и весь исходный код можно знать. Сложная задача для злоумышленника — по точкам P и Q найти число d. Для выбранных параметров это считается вычислительно непрактичным обычным способом.

3. Сначала файл превращают в короткий отпечаток

Подписывать большой файл напрямую неудобно. Поэтому программа вычисляет его хэш — короткий отпечаток фиксированной длины.

В этой работе используется хэш-функция «Стрибог-256». Она читает байты файла и выдаёт 256 бит, то есть 32 байта результата. Маленькое изменение файла сильно меняет весь отпечаток.

Файл M → H(M) → 256-битный отпечатокH — функция «Стрибог-256», M — точные байты файла.

Дальше результат хэширования приводится к диапазону от 0 до q−1:

e = H(M) mod q; если e = 0, то e = 1

Значение e — число, с которым дальше работает подпись. Важно: программа читает файл как двоичные данные. Перевод строки, пробел или другой байт тоже часть файла. Поэтому даже замена окончания строки может привести к отказу проверки.

Хэширование — не шифрование. По хэшу нельзя восстановить исходный файл, но хэш не скрывает файл: его можно читать отдельно как обычный документ.

4. Как создаётся подпись

Чтобы подписать файл, программе нужны его байты и закрытый ключ d. Она сначала считает e, а затем выполняет четыре шага.

  1. Выбирает новое случайное число k из диапазона от 1 до q−1.
  2. Умножает базовую точку на k: C = k·P. Получается точка с координатами (xC, yC).
  3. Считает первое число подписи: r = xC mod q.
  4. Считает второе число подписи: s = (r·d + k·e) mod q.
Подпись = (r, s)В файле подписи лежат две шестнадцатеричные строки: r=... и s=....

Закрытый ключ d участвует в вычислении s, но не записывается в файл подписи. Поэтому получатель не получает секретный ключ вместе с документом.

Число k должно быть свежим и секретным для каждой подписи. Если повторно использовать одно и то же k, злоумышленник, увидев несколько подписей, может вычислить закрытый ключ. Поэтому программа получает случайные числа из системного генератора Windows через BCrypt.

5. Как проверяется подпись

Получателю нужны файл, пара чисел (r, s) и открытый ключ Q. Закрытый ключ для проверки не нужен.

  1. Получатель заново хэширует полученный файл и получает то же число e, если файл не меняли.
  2. Вычисляет обратное к e число по модулю q: e⁻¹. Это аналог деления в арифметике по модулю.
  3. Получает два числа: z1 = s·e⁻¹ mod q и z2 = (q−r)·e⁻¹ mod q.
  4. Складывает две точки: C' = z1·P + z2·Q.
  5. Считает v = xC' mod q. Подпись верна тогда и только тогда, когда v = r.

Почему совпадение получается для настоящей подписи?

Открытый ключ — это Q = d·P. Подставим это и формулу подписи в выражение для точки проверки:

C' = (s/e)·P + ((q−r)/e)·Q
C' = ((s − r·d)/e)·P
s − r·d = k·e, значит C' = k·P = CЗдесь деление — умножение на обратное по модулю q; q−r работает как −r по модулю q.

Получилась та же точка C, которую программа создала при подписании. Значит, её координата x даст исходное r. Если файл изменён, число e уже другое, равенство ломается, и проверка отклоняет подпись.

Программа также проверяет, что координаты открытого ключа принадлежат кривой, что сам ключ имеет нужный порядок, а числа r и s находятся в допустимом диапазоне.

6. Что конкретно делает эта программа

keygen — создаёт ключи
Системный генератор Windows выдаёт случайное d. Программа вычисляет Q = d·P и записывает закрытый и открытый ключи в разные файлы.
sign — подписывает файл
Читает закрытый ключ и файл, считает «Стрибог-256», получает e, выбирает случайное k и сохраняет r и s.
verify — проверяет подпись
Читает открытый ключ, файл и подпись, пересчитывает хэш и выполняет проверочные вычисления. При успехе печатает Signature is valid; иначе — Signature verification failed.

Арифметика 256-битных чисел, операции с точками, формирование подписи и «Стрибог-256» написаны в проекте на C++. Внешняя криптографическая библиотека не используется. BCrypt нужен только для безопасной случайности Windows.

Ключи и подпись — обычные текстовые файлы с шестнадцатеричными значениями. Например, закрытый ключ хранит поле d, открытый — поля x и y, подпись — поля r и s.

7. Алгоритм именно так, как он сделан в исходнике

В прошлых разделах была общая идея. Здесь пройдём по внутренним деталям программы в том порядке, в котором их встречает код в src/crypto.hpp.

Важное уточнение: цифровая подпись не исправляет и не восстанавливает ошибочные байты. Она проверяет файл. Если файл изменили, программа обнаружит, что старая подпись к нему не подходит, и напечатает Signature verification failed. Исправить файл после этого должен человек или другая программа, имея правильную копию.

Сначала весь алгоритм целиком

Запомни одну цепочку. Создание ключей готовит секрет и соответствующий ему открытый ключ. Подписание связывает файл с секретом. Проверка пересчитывает математику только по файлу, подписи и открытому ключу.

ОДИН РАЗ: СОЗДАТЬ ПАРУ КЛЮЧЕЙ
    случайное d                    закрытый ключ
    Q = d * P                      открытый ключ

ДЛЯ ПОДПИСАНИЯ ФАЙЛА M
    e = Стрибог256(M) mod q        число из содержимого файла
    выбрать новое случайное k
    C = k * P
    r = x-координата(C) mod q
    s = (r * d + k * e) mod q
    сохранить (r, s)

ДЛЯ ПРОВЕРКИ
    снова получить e из файла M
    z1 = s / e mod q
    z2 = (q - r) / e mod q
    C' = z1 * P + z2 * Q
    подпись верна, если x-координата(C') mod q == r

Знак / e mod q в псевдокоде означает умножение на обратное число e⁻¹. Именно так это сделано в коде через powMod(e, q−2, q).

Самое короткое объяснение: при подписании случайное k создаёт точку C = k·P. Подпись хранит два числа, которые позволяют проверяющему восстановить эту точку из открытого ключа и подписи. Если содержимое файла другое, число e меняется, точка уже не совпадает, а значит не совпадает и проверяемое r.

Не перепутай два модуля

В программе одновременно используются p и q. Это два разных круга счёта, каждый нужен для своей части:

  • mod p используется внутри координат эллиптической кривой: при проверке её уравнения, сложении и удвоении точек.
  • mod q используется для чисел подписи: закрытого ключа d, случайного k, хэша e, чисел r и s.

Можно думать о p как о правилах для координат точек, а о q — как о размере круга, в котором живут ключи и числа подписи. Координата x точки сначала существует по модулю p, потом для формулы подписи отдельно берётся x mod q.

7.1. Как программа хранит большое число

Число до 256 бит не помещается в обычный тип uint64_t, поэтому структура UInt256 хранит его в четырёх ячейках по 64 бита: limb[0], limb[1], limb[2], limb[3]. Нулевая ячейка содержит младшие биты, третья — старшие.

Например, 256-битное число — это как длинное число, разрезанное на четыре кусочка. При сложении программа идёт от младшего кусочка к старшему и передаёт перенос, если кусочек переполнился. При вычитании так же передаётся заём. Функции addRaw и subRaw выполняют эти обычные операции.

Функции fromHex и toHex переводят числа между внутренним видом и строкой из 64 шестнадцатеричных цифр. Это нужно для файлов ключей и подписи.

7.2. Как выполняется арифметика «по модулю»

После сложения по модулю m результат должен снова попасть в диапазон от 0 до m−1. Поэтому addMod складывает числа и при необходимости вычитает модуль. subMod делает вычитание с переходом через модуль.

Например, 29 mod 17 = 12: после 17 счёт как бы начинается заново. Поэтому 5·7 mod 17 = 35 mod 17 = 1. Результат умножения по модулю всегда остаётся небольшим, даже если обычное произведение было бы огромным.

Для такого умножения здесь не используется готовая библиотека больших чисел. mulMod смотрит на биты второго множителя. Если очередной бит равен 1, добавляет текущий удвоенный первый множитель к ответу. Затем удваивает его для следующего бита. Это похоже на умножение столбиком, только в двоичной системе и с остатком по модулю. Так программа считает, например, r·d mod q и k·e mod q в формуле подписи.

powMod возводит число в степень методом последовательных квадратов: читает биты степени, на каждом шаге возводит основание в квадрат и умножает его на ответ, когда бит равен 1. reduceMod проходит биты большого числа слева направо и по одному строит его остаток.

большое умножение → повторные сложения и удвоения
обратное число e⁻¹ mod q → e^(q−2) mod qПоследняя формула работает потому, что q — простое число. В коде обратное число вычисляет powMod.

7.3. Как программа считает точки кривой

Точка хранится в структуре Point. В ней есть координаты x, y, дополнительная координата z и флаг бесконечности. Точка на бесконечности — это нейтральный элемент: как прибавить ноль, она не меняет другую точку.

Чтобы быстро считать подпись, программа не делит числа после каждого сложения точек. Она держит точки в проективных, точнее якобиановых, координатах (X, Y, Z). Это другой способ записать ту же самую точку: обычные координаты равны x = X/Z² и y = Y/Z³ по модулю p. Он позволяет складывать и удваивать точки, обходясь умножениями по модулю p, без дорогого деления на каждом шаге. В конце toAffine переводит точку обратно в обычные координаты.

Представь точки кривой на рисунке. Чтобы сложить две разные точки, проводят через них прямую, находят третье пересечение с кривой и отражают его относительно горизонтальной оси. Чтобы удвоить одну точку, вместо прямой берут касательную в этой точке. Это только способ представить правило глазами: в C++ программа выполняет соответствующие формулы над числами.

  • pointDouble считает точку A + A.
  • pointAdd складывает две точки. Если они одинаковые, вызывает удвоение; если они противоположные, возвращает точку на бесконечности.
  • scalarMultiply(P, n) считает n·P. Начинает с точки на бесконечности и проходит биты n от младшего к старшему: для бита 1 прибавляет текущую точку, а перед следующим битом удваивает её.
  • toAffine находит обратное к z по модулю p и получает x = X/z², y = Y/z³.

Важно: n·P — это не «умножить x-координату на n». Здесь умножается точка: это специальное сложение одной и той же точки P с собой. Ответ тоже точка, то есть пара координат. Для ключа программа получает Q=d·P; для подписи — временную точку C=k·P.

Вот как цикл scalarMultiply получает 13·P. Это учебный пример порядка сложений; настоящая программа подставляет 256-битные d или k.

13 в двоичной записи = 1101

R = точка на бесконечности; A = P
бит 0 равен 1: R = R + A = P;       A удваивается и становится 2P
бит 1 равен 0: R остаётся P;         A удваивается и становится 4P
бит 2 равен 1: R = P + 4P = 5P;     A удваивается и становится 8P
бит 3 равен 1: R = 5P + 8P = 13P

результат: точка R = 13P, то есть её координаты (x, y)

Компьютер не рисует кривую и не передвигает точку по картинке. Он берёт координаты и применяет формулы сложения или удвоения; все промежуточные координаты считаются по модулю p. Конкретные координаты ответа зависят от выбранных P и числа n.

Посмотреть формулы сложения и удвоения точек, которые использует код

Эти формулы работают с якобиановыми координатами (X, Y, Z). Каждое умножение, сложение и вычитание ниже выполняется по модулю p.

Для удвоения точки сначала считаются XX=X², YY=Y², YYYY=YY² и ZZ=Z². Потом:

S = 4·X·YY
M = 3·XX + a·ZZ²
X3 = M² - 2·S
Y3 = M·(S - X3) - 8·YYYY
Z3 = (Y + Z)² - YY - ZZ

новая точка = (X3, Y3, Z3)

Для сложения двух точек (X1,Y1,Z1) и (X2,Y2,Z2) код сначала приводит их к общему масштабу, чтобы понять, равны ли координаты:

Z1Z1 = Z1²                 Z2Z2 = Z2²
U1 = X1·Z2Z2               U2 = X2·Z1Z1
S1 = Y1·Z2·Z2Z2            S2 = Y2·Z1·Z1Z1

если U1 = U2 и S1 = S2: выполнить удвоение
если U1 = U2 и S1 != S2: получить точку на бесконечности
иначе:
    H = U2 - U1
    I = (2·H)²
    J = H·I
    R = 2·(S2 - S1)
    V = U1·I
    X3 = R² - J - 2·V
    Y3 = R·(V - X3) - 2·S1·J
    Z3 = ((Z1 + Z2)² - Z1Z1 - Z2Z2)·H

Это не отдельные правила подписи, а способ эффективно выполнять операцию + между точками. Именно эти сложение и удвоение вызываются внутри умножения точки на число.

7.4. Как в исходнике считается «Стрибог-256»

Главная мысль: Стрибог не превращает каждый байт файла в отдельный байт хэша. Он хранит рабочее состояние h размером 64 байта. Очередной блок файла смешивается с этим состоянием, и получается новое состояние. Поэтому поздние блоки зависят от того, что уже было в файле.

В варианте «Стрибог-256» рабочее состояние всё равно 64 байта. Просто в конце программа берёт из него 32 байта, то есть 256 бит.

Шаг 1. Прочитать файл и разрезать его на блоки

hashFile открывает файл как последовательность байтов, без попытки понять текст или кодировку. streebog256 обрабатывает блоки размером 64 байта. 64 байта — это 512 бит.

В коде полные блоки берутся с конца файла к началу. Например, для файла размером 130 байт сначала берутся байты 66–129, потом байты 2–65. Оставшиеся байты 0 и 1 попадут в последний неполный блок.

Шаг 2. Если блок неполный, добавить разделитель

Алгоритму важно отличать конец данных от нулевых байтов внутри файла. Поэтому перед оставшимися байтами ставится специальный байт 01, а свободное место заполняется нулями.

Например, если файл содержит ровно один байт 41, код собирает 64-байтовый блок так: много нулей, затем 01, затем 41. Если файл пустой, блок всё равно создаётся: 63 нулевых байта и последний байт 01. Если файл ровно 64 байта, сначала обрабатывается полный блок, а после него всё равно обрабатывается отдельный пустой блок с разделителем.

Шаг 3. Подготовить три рабочие переменные

  • h — текущее состояние, то есть накопленная память о блоках. Для «Стрибог-256» все его 64 байта сначала равны 01.
  • N — сколько бит полных блоков уже было обработано. Сначала это ноль.
  • Sigma — внутренний накопитель суммы обработанных блоков. Он тоже начинается с нуля. Это часть самого Стрибога, а не отдельная контрольная сумма файла.

Для каждого полного блока код вызывает compress(h, N, block), затем прибавляет 512 к N и сам блок к Sigma. У сложения Sigma тот же размер 512 бит; перенос за пределы 64 байт отбрасывается.

Шаг 4. Перемешать один блок: замена, перестановка, смешивание

Функция lps получает 64 байта и проводит их через три слоя. Важно: это не три разных хэша, а три последовательных изменения одного и того же блока.

  1. S — замена байтов. Каждый байт служит номером в таблице Pi, и на его место ставится значение из таблицы. Например, 00 заменяется на FC, 01 на EE, 02 на DD. Это нелинейный слой: замена не сводится к простому сложению.
  2. P — перестановка. 64 байта меняют места по таблице Tau. Например, первые байты нового порядка берутся из позиций 0, 8, 16, 24, 32, 40, 48 и 56 старого порядка. Байт, стоявший рядом с другим, после перестановки оказывается далеко от него.
  3. L — линейное смешивание. Восемь байтов берутся как группа из 64 бит. Для каждого бита, который равен 1, код выполняет XOR с соответствующей 64-битной константой из таблицы A. Получившееся слово заменяет эту группу байтов. Так изменение одного бита влияет на многие выходные биты.

XOR — это простая операция над битами: 0 XOR 0 = 0, 1 XOR 1 = 0, а если биты разные, результат 1. Функция xorBlock делает её отдельно для каждой пары байтов двух 64-байтовых массивов.

Шаг 5. Пропустить блок через 12 раундов сжатия

Функция compress соединяет старое состояние h, счётчик N и текущий блок m. Она заводит временный ключ K и временное состояние state, а затем 12 раз обновляет их с помощью lps. C[i] — разные заранее заданные константы раундов.

K = LPS(h XOR N)
state = m

повторить 12 раз:
    state = LPS(state XOR K)
    K = LPS(K XOR C[i])

новое h = state XOR K XOR h XOR m

Слово «сжатие» здесь означает: из старого состояния и очередного 64-байтового блока получается новое 64-байтовое состояние. Исходный блок после этого можно забыть — его влияние уже попало в h.

Шаг 6. Завершить хэш и получить 32 байта

После последнего, возможно неполного блока, код добавляет в N число бит из остатка, а в Sigma — блок с разделителем. Так в завершение попадают и общая длина сообщения, и накопленная сумма блоков. Затем делаются ещё два завершающих сжатия: сначала состояние смешивается со счётчиком N, потом — с Sigma. Из итоговых 64 байт состояния берутся первые 32 байта. Это и есть результат «Стрибог-256».

Вся последовательность для одного файла выглядит так:

файл → блоки по 64 байта → разделитель последнего блока → 12 раундов на каждый блок → финальное смешивание N и Sigma → 32 байта

Наконец, hashToScalar читает эти 32 байта как число, берёт остаток по модулю q и, если остаток равен нулю, заменяет его на 1. Это число e уже использует алгоритм подписи.

7.5. Порядок работы keygen

  1. randomScalar просит Windows BCrypt выдать 32 случайных байта.
  2. Байты превращаются в число d. Если получилось 0 или число не меньше q, запрос повторяется. Так закрытый ключ гарантированно попадает в диапазон 1 ≤ d < q.
  3. Программа вычисляет точку Q = d·P, переводит её в обычные координаты и записывает файлы.
  4. Закрытый файл содержит строку d=.... Открытый файл содержит две строки: x=... и y=....

7.6. Порядок работы sign

  1. parseFields читает закрытый ключ и проверяет имя поля и длину шестнадцатеричного числа. Закрытый ключ дополнительно проверяется на диапазон.
  2. hashFile читает именно байты файла; hashToScalar получает Стрибог-256, приводит число к модулю q, а нулевой результат заменяет на 1.
  3. Программа случайно выбирает k тем же способом, что и ключ. Вычисляет C = k·P и переводит точку в координаты x и y.
  4. Считает r = x mod q. Если r = 0, выбирает другое k.
  5. Считает s = (r·d + k·e) mod q. Если s = 0, тоже начинает с нового k.
  6. Записывает r и s в файл подписи. Ни d, ни k в файл подписи не записываются.

Итог команды sign — не новый зашифрованный файл, а отдельная маленькая подпись из двух чисел. Исходный файл остаётся читаемым. Числа d и k в подпись не попадают.

7.7. Порядок работы verify

  1. Программа читает открытый ключ и подпись. Проверяет, что координаты ключа меньше p и лежат на кривой.
  2. Дополнительно вычисляет q·Q. Результат обязан быть точкой на бесконечности; так отбрасывается открытый ключ неправильного порядка.
  3. Проверяет, что r и s не равны нулю и каждое меньше q.
  4. Заново вычисляет хэш проверяемого файла и число e.
  5. Вычисляет e⁻¹ mod q, затем z1 = s·e⁻¹ mod q и z2 = (q−r)·e⁻¹ mod q.
  6. Считает точку C' = z1·P + z2·Q. Если это точка на бесконечности, проверка завершается отказом.
  7. Берёт её координату x, приводит её к модулю q и сравнивает с r. Равенство означает успех.

Последнее сравнение и есть способ обнаружить ошибку в файле. Допустим, после подписания поменяли букву. Проверка заново считает хэш, поэтому вместо прежнего e получает другое число. Из-за этого меняются z1, z2 и восстановленная точка C'. Обычно её x-координата уже не даёт исходное r, поэтому программа отвергает подпись. Она сообщает об изменении, но не знает, какая буква была раньше, и не может починить файл.

Мини-пример: почему при проверке восстанавливается та же точка

Настоящие числа ГОСТ огромные, поэтому возьмём маленькие учебные числа только для арифметики подписи. Пусть модуль q = 17, закрытый ключ d = 5, одноразовое число k = 3, хэш файла e = 4, а получившееся из точки число r = 6.

При подписании программа получает:

s = (r·d + k·e) mod q
s = (6·5 + 3·4) mod 17
s = 42 mod 17 = 8

Теперь проверяющий знает r=6, s=8, e=4 и открытый ключ Q=5·P. Обратное к 4 по модулю 17 равно 13, потому что 4·13 = 52, а остаток от деления 52 на 17 равен 1.

z1 = s·e⁻¹ mod q = 8·13 mod 17 = 2
z2 = (q−r)·e⁻¹ mod q = 11·13 mod 17 = 7
C' = z1·P + z2·Q
C' = 2·P + 7·(5·P) = 37·P = 3·P

Последнее равенство верно, потому что 37 mod 17 = 3. А 3 — это исходное одноразовое число k, то есть проверяющий восстановил C' = k·P = C. В настоящей программе вместо сложения коэффициентов выполняются операции над точками кривой, но математика совпадает.

Это только игрушечный пример формулы. В программе используются реальные параметры TC26 paramSetA с 256-битными числами. Число 17 здесь выбрано лишь для того, чтобы можно было проверить умножение и остаток вручную. Оно не является параметром кривой лабораторной.

Особенность учебного кода: арифметика написана для демонстрации алгоритма, а не для защиты производственной системы. В вычислениях есть ветвления, зависящие от битов секретного числа; также закрытый ключ хранится в обычном текстовом файле без пароля. Для настоящих секретных данных используют проверенные криптографические библиотеки и защищённое хранение ключей.

8. Сборка и запуск в Windows

Открой PowerShell в папке Lab 6. Для компиляции нужен установленный Windows-сборщик MinGW-w64 g++.

g++ -std=c++17 -O2 src/main.cpp -o Lab6.exe -lbcrypt

.\Lab6.exe keygen private.key public.key
.\Lab6.exe sign private.key test.txt test.sig
.\Lab6.exe verify public.key test.txt test.sig

Проверка должна вывести Signature is valid. Теперь сделай копию файла, измени её и попробуй проверить старую подпись:

Copy-Item test.txt tampered.txt
Add-Content tampered.txt 'Changed content'
.\Lab6.exe verify public.key tampered.txt test.sig

Для изменённого файла программа должна написать Signature verification failed и завершиться с кодом 2.

Не отправляй файл private.key другим людям. Если кто-то получит его, он сможет выдавать свои файлы за подписанные тобой. Файл public.key можно раздавать для проверки подписей.

9. Словарь без заумных слов

Байт
Маленькая единица данных: число от 0 до 255. Файл для программы — это последовательность байтов.
Хэш
Короткий отпечаток файла. Он помогает заметить изменение, но не прячет и не восстанавливает содержимое.
Закрытый ключ
Секретное число d, которое даёт владельцу возможность создавать подписи.
Открытый ключ
Точка Q, которую можно раздавать. Она позволяет проверять подписи, но практически не раскрывает закрытый ключ.
Модуль
Правило «после большого числа начинаем счёт заново», как на часах. Запись a mod q означает остаток от деления a на q.
Эллиптическая кривая
Набор точек с заданной формулой и правилами сложения. Подпись использует эти точки вместо обычных больших чисел.
Случайное число k
Одноразовое секретное число для одной подписи. Его нельзя публиковать или повторно использовать.
Проверка целостности
Проверка, что файл остался тем же самым по байтам после подписания.

Эта страница объясняет логику учебной реализации. Главная цепочка такая: файл → хэш → подпись закрытым ключом → проверка открытым ключом.
