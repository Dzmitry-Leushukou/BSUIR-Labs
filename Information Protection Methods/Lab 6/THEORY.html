ГОСТ 34.10: краткая теория

Стрибог-256 получает отпечаток документа. ГОСТ 34.10 связывает этот отпечаток с закрытым ключом и позволяет проверить подпись открытым ключом.

1. Откуда берутся параметры и точки

В программе заранее заданы параметры кривой TC26 paramSetA. При запуске они не генерируются.

y² ≡ x³ + a·x + b (mod p)
ОбозначениеЧто означает
pПростое число — модуль координат. Координаты точек и действия над ними считаются по модулю p.
a, bКоэффициенты уравнения кривой.
P = (xP, yP)Базовая точка. Её готовые координаты записаны в generatorX() и generatorY(); точка удовлетворяет уравнению кривой.
qБольшое простое число — порядок точки P: минимальное положительное число, для которого q·P = O. По нему считаются числа ключа и подписи.
OТочка на бесконечности — аналог нуля при сложении точек: A + O = A.

mod — остаток от деления: например, 20 mod 17 = 3. Строчная p — число, заглавная P — точка.

Что означает умножить точку

Координаты на число не умножаются. Запись 3·P означает P + P + P по специальным формулам кривой. Ответ — новая точка с двумя координатами.

Код ускоряет вычисление через удвоения и сложения: например, 13·P = P + 4·P + 8·P. Операции r·d и k·e, напротив, умножают обычные целые числа и дают числа.

2. Стрибог-256: как получается хэш

В Lab 6 используется Стрибог-256 по ГОСТ Р 34.11-2012. На входе — точные байты файла, на выходе — 32 байта. Рабочее состояние имеет размер 64 байта. Внутренние 512-битные значения хранятся старшим байтом вперёд — big-endian.

Начальное состояние

Один раз задаём h — 64 байта 01; N = 0 — число обработанных исходных битов; Σ = 0 — сумму блоков. Таблицы PI, TAU, A и 12 констант раундов заданы заранее.

Преобразование LPS: S → P → L

  1. S — замена: каждый байт заменяем значением PI[байт].
  2. P — перестановка: новый[i] = старый[TAU[i]]. То есть TAU[i] — старая позиция байта, i — новая.
  3. L — смешивание: берём 8 байтов, то есть 64 бита, задаём res = 0. Проверяем биты от старшего к младшему. Для каждого единичного бита с номером j выполняем res ^= A[j]. Полученные 64 бита заменяют эту группу. Повторяем для всех восьми групп, каждый раз обнуляя res и считая j от 0 до 63.

XOR (в C++ — ^) сравнивает биты: одинаковые дают 0, разные — 1. Это не обычное сложение с переносами.

Обработка одного блока — compress(h, N, m)

Полные блоки по 64 байта берём от начала файла к концу. Байты каждого блока разворачиваем и получаем m. Далее:

key = LPS(h XOR N)
state = m XOR key
rkey = key

повторить 12 раз:
    state = LPS(state)
    rkey = LPS(rkey XOR const[номер раунда])
    state = state XOR rkey

h = старое h XOR state XOR m

key и rkey — внутренние значения Стрибога, а не закрытый ключ подписи. После полного блока увеличиваем N на 512 и прибавляем m к Σ обычным сложением с переносами, оставляя младшие 512 бит. Повторяем для остальных полных блоков.

Остаток и завершение

Остаток оформляем в отдельный 64-байтовый блок: нули, байт 01, перевёрнутые байты остатка. Такой блок создаём даже при пустом остатке. Обрабатываем его так же, но увеличиваем N только на исходное число битов остатка, а к Σ прибавляем весь дополненный блок.

Затем ещё дважды вызываем обработку блока. В обоих случаях вместо счётчика подставляем ноль:

h = compress(h, 0, N)
h = compress(h, 0, Σ)

Берём первые 32 байта внутреннего массива h и разворачиваем их: digest[i] = h[31 − i]. Получаем хэш. В этой программе эти байты читаются как число старшим байтом вперёд и передаются алгоритму подписи.

3. ГОСТ 34.10: ключи и подпись

Ключи создаются один раз

Выбираем случайное целое d: 1 ≤ d < q
Q = d·P

Закрытый ключ — число d. Открытый ключ — точка Q = (xQ, yQ). Ключи не зависят от документа и могут использоваться для разных подписей.

Подписываем документ M

e = Streebog256(M) mod q
Если e = 0, принимаем e = 1

Выбираем новое случайное целое k: 1 ≤ k < q
C = k·P
C = (xC, yC)

r = xC mod q
s = (r·d + k·e) mod q

Из временной точки C берём её первую координату xC и получаем r. Число s связывает r, секрет d, одноразовое k и отпечаток документа e.

Если r = 0 или s = 0, выбираем новое k и повторяем вычисления. Ключи d и Q сохраняются. Число k должно быть новым и секретным для каждой подписи.

Подпись — пара чисел (r, s). Получателю нужны документ, подпись и открытый ключ Q. Секреты d и k ему не передаются.

4. Как проверяется подпись

Сначала проверяем 1 ≤ r, s < q. Открытый ключ должен лежать на кривой и удовлетворять q·Q = O. Затем:

e = Streebog256(полученный документ) mod q
Если e = 0, принимаем e = 1

u = e⁻¹ mod q = e^(q−2) mod q

z1 = s·u mod q
z2 = (q−r)·u mod q

C' = z1·P + z2·Q

u — обратное число: e·u mod q = 1. Умножение на него заменяет деление на e. В z2 используется именно q−r.

Если C' — точка на бесконечности, отклоняем подпись. Иначе у вычисленной точки есть координаты:

C' = (x', y')
v = x' mod q
Подпись корректна, если v = r

Здесь x' — первая координата полученной точки. При подписании r тоже получали из первой координаты точки C.

5. Смысл проверки через точки

Для правильной подписи первая проверочная точка получается как C с добавкой T, а вторая — как противоположная этой добавке точка:

T = (r·u mod q)·Q
A = z1·P = C + T
B = z2·Q = −T
C' = A + B = (C + T) + (−T) = C

Почему A = C + T: подставляем s = r·d + k·e mod q и используем Q = d·P, e·u mod q = 1:

A = (s·u mod q)·P
A = (r·u mod q)·Q + k·P = T + C

Почему B = −T: поскольку q·Q = O, множитель q−r действует как −r. Противоположные точки дают T + (−T) = O, поэтому добавка уничтожается и остаётся исходная C = k·P.

Исходную C получателю не передавали. Поэтому он проверяет её ориентир из подписи: x' mod q = r. Закрытый ключ d для этих действий не нужен.

Если документ изменили

Получаем почти наверняка другое e'. Добавки тоже сокращаются, но остаётся точка C' = (k·e·(e')⁻¹ mod q)·P, где e — прежнее значение при подписании. Обычно это другая точка, и её координата почти наверняка не даёт прежнее r. Проверка завершается отказом.

Подпись обнаруживает изменение, но не исправляет файл. Она также не шифрует содержимое.
