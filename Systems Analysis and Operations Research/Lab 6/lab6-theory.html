1. Что требуется найти

Двудольный граф — это граф, вершины которого разбиты на две группы. Ребро соединяет вершину слева с вершиной справа, но не вершины одной группы между собой.

Паросочетание — набор рёбер без общих вершин. Если вершина уже участвует в выбранном ребре, второе ребро с ней выбрать нельзя. Нужно найти паросочетание, в котором как можно больше рёбер.

Левая доля V1             Правая доля V2

   u1  --------------------  v1
   u2  -----------+--------  v1
                  +--------  v2
   u3  --------------------  v3
Ребро исходного графа

Здесь можно выбрать пары (u1,v1), (u2,v2), (u3,v3). Вершины не повторяются, значит размер паросочетания равен 3.

Представь людей и задачиЛюди — левая доля, задачи — правая. Ребро значит, что человек умеет выполнять задачу. Паросочетание назначает разным людям разные задачи. Максимальное паросочетание назначает задачу максимально возможному числу людей.

2. Главная идея: найти путь и переставить пары

Допустим, сейчас выбрана только пара (u1,v1). Свободная вершина u2 тоже связана с v1, но просто добавить (u2,v1) нельзя: тогда у v1 было бы две пары.

Посмотрим, можно ли освободить v1, пересадив u1 на другую вершину:

u2 --свободное ребро--> v1 --выбранное ребро назад--> u1
                                                    |
                                             свободное ребро
                                                    v
                                                   v2

Путь: u2 -> v1 -> u1 -> v2
После перестройки: (u2,v1), (u1,v2)
Добавляемое реброВыбранное ребро, которое снимем

Путь начинается в свободной левой вершине, заканчивается в свободной правой и чередует невыбранные и выбранные рёбра. После перестройки старую пару убираем, а два свободных ребра выбираем. Было одно ребро, стало два.

Почему размер всегда растёт на 1На чередующемся пути свободных рёбер на одно больше, чем уже выбранных. Поэтому если убрать выбранные рёбра пути и добавить свободные, общее количество пар увеличится ровно на единицу.

3. Ориентированный граф G*

Методичка превращает поиск такого пути в обычный поиск пути от источника s до стока t. Правила направления дуг такие:

ДугаПростое значение
s -> uu свободна и может начать путь.
u -> vРебро не выбрано; по нему можно добавить пару.
v -> uРебро выбрано; по нему можно вернуться и снять прежнюю пару.
v -> tv свободна и может завершить путь.
Зачем менять направление у выбранных рёберКогда путь приходит в занятую правую вершину, он должен пройти назад по её текущей паре и освободить её. Именно поэтому такая дуга направлена из правой доли в левую.

В коде G* не сохраняется отдельным списком дуг. Программа определяет направление на лету по массивам текущего паросочетания. Это то же представление графа, только без создания отдельной структуры для дуг.

4. Что в коде за что отвечает

Данные исходного графа

Структура BipartiteGraphфрагмент C++
struct BipartiteGraph {
    int leftSize = 0;
    int rightSize = 0;
    vector<vector<int>> adjacent;
};

leftSize и rightSize — размеры долей. adjacent[u] содержит номера всех правых вершин, соединённых ребром с левой вершиной u. Внутри индексы начинаются с нуля; при печати к ним прибавляется единица.

Текущее паросочетание

Соответствия в обе стороныполя класса MaximumMatching
vector<int> matchedLeft;
vector<int> matchedRight;

matchedLeft[u] = v значит, что u сейчас соединена в паросочетании с v. matchedRight[v] = u хранит обратное соответствие. Значение -1 означает «свободна».

Очередь, посещённость и родители BFS

Основа поиска в ширинуфрагмент findAugmentingPath
parent.assign(vertexCount, -1);
vector<bool> visited(vertexCount, false);
queue<int> pending;

visited[source] = true;
pending.push(source);

while (!pending.empty()) {
    int current = pending.front();
    pending.pop();
    // Обрабатываем дуги G* из current.
}

pending — очередь вершин на обработку. visited защищает от повторных заходов. parent запоминает предшественника, чтобы восстановить найденный путь.

Из источника в свободные левые вершины

Реализация дуг s -> uфрагмент findAugmentingPath
if (current == source) {
    for (int left = 0; left < graph.leftSize; ++left) {
        if (matchedLeft[left] == -1 && !visited[left]) {
            visited[left] = true;
            parent[left] = source;
            pending.push(left);
        }
    }
    continue;
}

В очередь попадают только свободные левые вершины. Если вершина уже занята, она не может быть началом увеличивающего пути.

Из левой вершины по свободным рёбрам

Реализация дуг u -> vфрагмент findAugmentingPath
if (current < graph.leftSize) {
    int left = current;
    for (int right : graph.adjacent[left]) {
        if (matchedLeft[left] == right) continue;
        int next = rightVertex(right);
        if (visited[next]) continue;
        visited[next] = true;
        parent[next] = current;
        pending.push(next);
    }
}

Перебираются исходные рёбра из левой вершины. Если ребро уже входит в matching, оно пропускается. Оставшиеся рёбра направлены слева направо.

Из правой вершины: в сток или назад по выбранному ребру

Реализация дуг v -> t и v -> uфрагмент findAugmentingPath
int right = current - graph.leftSize;
if (matchedRight[right] == -1) {
    if (!visited[sink]) {
        visited[sink] = true;
        parent[sink] = current;
        finish = sink;
        return true;
    }
} else {
    int next = matchedRight[right];
    if (!visited[next]) {
        visited[next] = true;
        parent[next] = current;
        pending.push(next);
    }
}

Свободная правая вершина означает, что найден конец пути, поэтому BFS возвращает true. Занятая вершина ведёт назад к своей левой паре.

Восстановление пути

Идём по parent назад, затем разворачиваемфрагмент pathWithoutTerminals
vector<int> reversed;
for (int vertex = parent[finish];
     vertex != source && vertex != -1;
     vertex = parent[vertex]) {
    reversed.push_back(vertex);
}
reverse(reversed.begin(), reversed.end());
return reversed;

Каждая вершина помнит, откуда в неё пришёл поиск. Так собирается цепочка назад от t. Функция не включает s и t в сам список вершин пути: они служебные.

Изменение паросочетания

Снять старые пары и добавить новыефрагмент augment
// Удалить выбранные ребра, пройденные назад.
for (size_t i = 1; i + 1 < path.size(); i += 2) {
    int right = path[i] - graph.leftSize;
    int left = path[i + 1];
    if (matchedRight[right] == left) {
        matchedRight[right] = -1;
        matchedLeft[left] = -1;
    }
}

// Добавить свободные ребра пути.
for (size_t i = 0; i + 1 < path.size(); i += 2) {
    int left = path[i];
    int right = path[i + 1] - graph.leftSize;
    matchedLeft[left] = right;
    matchedRight[right] = left;
}

Сначала снимаются старые пары на обратных шагах пути, затем добавляются новые пары на прямых. Оба массива обновляются вместе, чтобы информация слева направо и справа налево не разошлась.

Повторение до остановки

Основной цикл solveфрагмент C++
while (true) {
    vector<int> parent;
    int finish = -1;
    if (!findAugmentingPath(parent, finish)) break;

    ++iterations;
    vector<int> path = pathWithoutTerminals(parent, finish);
    augment(path);
}

Нашли путь — перестроили matching и пробуем снова. Не нашли — выходим из цикла.

5. Пример полного выполнения

Входной файл input.txt содержит:

3 3 4
1 1
2 1
2 2
3 3
  1. Первый BFS. Все вершины свободны. Находится путь s->u1->v1->t. Добавляем (u1,v1).
  2. Следующий BFS. Ищем путь из любой свободной левой вершины. Из u2 достижимы v1 и v2. v1 занята, можно пройти назад к u1, но дальше нет подходящего свободного ребра. BFS также видит путь s->u2->v2->t и добавляет (u2,v2).
  3. Третий BFS. Находит s->u3->v3->t и добавляет (u3,v3).
  4. Финальный BFS. Свободных левых вершин больше нет, значит из s путь не начинается. t недостижима, алгоритм останавливается. Размер matching равен 3.
Пример, где пара действительно перестраиваетсяПусть рёбра графа: (u1,v1), (u1,v2), (u2,v1). После выбора (u1,v1) путь для следующей итерации: s->u2->v1->u1->v2->t. Убираем (u1,v1), добавляем (u2,v1) и (u1,v2). Число пар выросло с одной до двух.

6. Почему полученное решение максимальное

Теорема БержаПаросочетание максимально по размеру тогда и только тогда, когда увеличивающего пути больше нет.

В нашей реализации увеличивающий путь есть тогда и только тогда, когда достижима вершина t из s в ориентированном графе G*. Каждый такой путь увеличивает matching на 1. Когда поиск возвращает false, теорема Бержа гарантирует, что можно остановиться: текущий matching максимален.

Число итераций конечно: количество пар не может превысить размер меньшей доли.

Оценка времениОдин BFS работает за O(V + E). Увеличивающих путей не больше min(|V1|, |V2|), поэтому оценка всего алгоритма: O(min(|V1|, |V2|) · (V + E)). Память: O(V + E).

Термин «максимальное» здесь означает самое большое по количеству рёбер. Это не просто «уже нельзя добавить ещё одно ребро напрямую»: иногда решение можно улучшить, только сначала перестроив старые пары.

7. Ввод и запуск

Первая строка задаёт |V1| |V2| |E|: размеры долей и количество рёбер. Далее идёт по одной паре номеров вершин на ребро. Нумерация во входном файле начинается с 1.

Запуск с файлом:

main.exe input.txt

Запуск с подробным выводом путей и состояния ориентированного графа:

main.exe --detailed input.txt

В подробном режиме видно: найденный путь, перестройку по шагу 5 методички, состояние matching и дуги G* после перестройки.

8. Ответ для защиты

«Программа ищет максимальное паросочетание методом увеличивающих путей. Для текущего паросочетания рассматривается ориентированный граф: источник соединён со свободными вершинами первой доли, невыбранные рёбра направлены слева направо, выбранные — справа налево, а свободные вершины второй доли соединены со стоком. Поиск в ширину находит путь от источника к стоку. Если путь найден, крайние дуги удаляются, промежуточные меняют направление. Это перестраивает matching и увеличивает его на единицу. Поиск повторяется, пока путь существует. Когда путь не найден, по теореме Бержа найдено максимальное паросочетание».

matchedLeft, matchedRightТекущее паросочетание, доступное с обеих сторон.
visitedПосещённые BFS вершины.
parentПредшественник вершины для восстановления пути.
