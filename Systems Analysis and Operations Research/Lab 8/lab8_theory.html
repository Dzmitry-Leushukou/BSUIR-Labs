1. Идея задачи

Представьте сеть труб. У каждой трубы есть ограничение: больше определённого количества воды через неё пропустить нельзя. Есть источник s, откуда вода выходит, и сток t, куда она должна прийти.

Задача о максимальном потоке состоит в том, чтобы провести из s в t как можно больше единиц потока, не превышая пропускную способность дуг.

Главная мысль: программа много раз ищет путь из истока в сток, по которому ещё можно добавить поток. На каждом найденном пути она добавляет максимально возможное количество, а потом ищет следующий путь.

Если путей больше нет, текущий поток является максимальным.

поток = 0
пока существует путь s -> t:
    найти минимальную свободную пропускную способность на пути
    увеличить поток по этому пути
результат = максимальный поток

В методичке вершины могут называться буквами, а во входном файле они нумеруются числами. Внутри C++ нумерация начинается с нуля, поэтому вершина 1 из файла хранится как индекс 0. При выводе программа снова прибавляет единицу.

3. Алгоритм Форда–Фалкерсона по методичке

  1. Начальный поток. Для всех дуг устанавливается f(a) = 0. В программе матрица flow создаётся заполненной нулями.
  2. Остаточная сеть. Для каждой дуги вычисляется, сколько потока ещё можно провести или отменить.
  3. Метод пометок. Из истока выполняется поиск по дугам с положительной остаточной пропускной способностью.
  4. Проверка стока. Если сток не помечен, путь s -> t отсутствует и алгоритм заканчивается.
  5. Восстановление пути. По меткам предыдущих вершин путь восстанавливается от стока к истоку.
  6. Поиск величины увеличения. На пути берётся минимум остаточных пропускных способностей: theta = min cf(a).
  7. Построение элементарного потока. На дугах найденного пути записывается theta, на остальных дугах — ноль.
  8. Обновление. Текущий поток изменяется по формуле из методички, затем поиск начинается снова.

4. Остаточная сеть и обратные дуги

Для дуги (u,v) методичка задаёт остаточную пропускную способность:

cf(u,v) = c(u,v) - f(u,v) + f(v,u)

Первая часть c(u,v) - f(u,v) — свободное место в прямой дуге. Если capacity равна 5, а поток равен 2, напрямую можно добавить ещё 3.

Вторая часть + f(v,u) позволяет отменить поток, который раньше прошёл в обратном направлении. Это необходимо, чтобы исправлять неудачный выбор предыдущего пути.

В коде формула записана напрямую:

long long residualCapacity(int from, int to) const {
    return capacity[from][to] - flow[from][to] + flow[to][from];
}

Методичка требует, чтобы вместе с каждой дугой была задана обратная дуга. Поэтому для дуги 1 -> 2 с capacity 3 во входе есть и строка 2 1 0. Нулевая исходная capacity не мешает: после отправки потока по 1 -> 2 остаточная возможность идти обратно появится за счёт члена + f(1,2).

6. Разбор функций

residualCapacity: остаточная capacity

Функция возвращает количество потока, которое можно добавить по направлению from -> to. Если результат равен нулю или меньше нуля, при поиске по этой дуге идти нельзя.

long long residualCapacity(int from, int to) const {
    return capacity[from][to] - flow[from][to] + flow[to][from];
}

findPath: метод пометок

Функция реализует очередь из методички. Массив parent хранит метку вершины: в нём записывается предыдущая вершина найденного пути.

bool findPath(vector<int>& parent) const {
    fill(parent.begin(), parent.end(), -1);
    queue<int> pending;
    pending.push(source);
    parent[source] = source;

    while (!pending.empty() && parent[sink] == -1) {
        int vertex = pending.front();
        pending.pop();
        for (int next = 0; next < vertexCount; ++next) {
            if (parent[next] != -1 || residualCapacity(vertex, next) <= 0)
                continue;
            parent[next] = vertex;
            pending.push(next);
        }
    }
    return parent[sink] != -1;
}

Условие parent[next] != -1 означает «вершина уже помечена». Условие residualCapacity(...) > 0 означает «дуга не нулевая в остаточной сети».

addArc: чтение дуги

bool addArc(int from, int to, long long arcCapacity) {
    if (hasArc[from][to]) return false;
    hasArc[from][to] = true;
    capacity[from][to] = arcCapacity;
    return true;
}

Функция запрещает повторное описание одной и той же направленной дуги и сохраняет её capacity.

hasAllReverseArcs: проверка условия методички

bool hasAllReverseArcs() const {
    for (int from = 0; from < vertexCount; ++from)
        for (int to = 0; to < vertexCount; ++to)
            if (hasArc[from][to] && !hasArc[to][from]) return false;
    return true;
}

Например, если во входе есть 1 -> 2, но нет 2 -> 1, программа завершится с ошибкой.

Восстановление пути и поиск theta

vector<int> path;
long long augmentation = numeric_limits<long long>::max();
for (int vertex = sink; vertex != source; vertex = parent[vertex]) {
    augmentation = min(
        augmentation,
        residualCapacity(parent[vertex], vertex)
    );
    path.push_back(vertex);
}
path.push_back(source);
reverse(path.begin(), path.end());

Путь восстанавливается с конца. Если метки говорят 4 <- 2 <- 1, после reverse получается обычная запись 1 -> 2 -> 4.

Построение элементарного потока и обновление

vector<vector<long long>> pathFlow(
    vertexCount, vector<long long>(vertexCount, 0)
);
for (size_t i = 1; i < path.size(); ++i)
    pathFlow[path[i - 1]][path[i]] = augmentation;

vector<vector<long long>> updatedFlow = flow;
for (int from = 0; from < vertexCount; ++from) {
    for (int to = 0; to < vertexCount; ++to) {
        updatedFlow[from][to] = max(
            0LL,
            flow[from][to] - flow[to][from] +
                pathFlow[from][to] - pathFlow[to][from]
        );
    }
}
flow.swap(updatedFlow);
maxFlow += augmentation;

Последняя формула соответствует методичке:

f'(a) = max(0, f(a) - f(ā) + fP(a) - fP(ā))

printResult: результат и минимальный разрез

Функция выводит значение максимального потока и поток по каждой входной дуге. Затем она ещё раз запускает поиск из истока по положительным остаточным capacity.

Все достижимые вершины образуют множество S, остальные — множество T. Пара S | T является минимальным разрезом.

7. Пошаговый пример

Для файла с сетью из методички:

4 10 1 4
1 2 3
2 1 0
1 3 2
3 1 0
2 3 2
3 2 0
2 4 1
4 2 0
3 4 2
4 3 0

Итерация 1

Поиск находит путь 1 -> 2 -> 4. Остаточные capacity равны 3 и 1, поэтому:

theta = min(3, 1) = 1

Поток на дугах пути увеличивается на 1. Общий поток становится 1.

Итерация 2

Поиск находит путь 1 -> 3 -> 4. Обе дуги имеют остаточную capacity 2:

theta = min(2, 2) = 2

Общий поток становится 1 + 2 = 3.

Остановка

Дуги 2 -> 4 и 3 -> 4 заполнены полностью. Сток больше не достижим по остаточной сети, поэтому алгоритм останавливается.

Maximum flow: 3
Minimum cut: S = {1, 2, 3}, T = {4}

8. Почему результат максимальный

Пока существует увеличивающий путь, текущий поток можно увеличить. Когда такого пути нет, множество вершин, достижимых из истока в остаточной сети, задаёт разрез S | T.

Все дуги из S в T имеют нулевую остаточную capacity, то есть полностью заполнены. Поэтому поток равен пропускной способности этого разреза.

Теорема о максимальном потоке и минимальном разрезе: величина максимального потока равна пропускной способности минимального разреза. Поэтому найденный результат нельзя улучшить.

В этой программе метод пометок реализован через BFS. Такой вариант часто называют Edmonds–Karp, но по сути он реализует требуемый метод Форда–Фалкерсона с поиском увеличивающего пути.
