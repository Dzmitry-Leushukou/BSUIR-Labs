1. Идея метода простыми словами

Нужно найти лучший план, где все переменные целые. Сначала разрешаем дробные значения, находим лучший дробный план, затем строим новое ограничение, которое отсекает эту дробную точку.

решить LP → проверить целочисленность → добавить срез → решить LP снова → повторять до целого оптимума

Симплекс-метод умеет решать задачу с непрерывными переменными. Для него x2 = 1.5 допустимо. Для исходной целочисленной задачи это недопустимо. Метод Гомори не перебирает варианты, а использует строку симплекс-таблицы, чтобы добавить ограничение: целые решения остаются, а текущая дробная вершина исчезает.

LP-релаксацияВременно убираем условие x ∈ Zⁿ.
Дробный оптимумИщем дробную базисную переменную.
СрезБерём дробные части строки таблицы и добавляем ограничение.
ИтогПовторяем, пока оптимальный план не станет целым.

3. Алгоритм по шагам методички, повторённый до решения

LP-релаксация. Убираем требование целочисленности и решаем обычную задачу ЛП.
Статус. Если LP несовместна, исходная задача несовместна. Если цель не ограничена сверху, сообщаем об этом.
Проверка. Если оптимальный план целый, он является оптимальным планом целочисленной задачи.
Дробная строка. Выбираем базисную переменную с дробным значением.
Базис и небазис. Нужная строка таблицы раскладывается по небазисным переменным.
Дробные части. Берём дробные части коэффициентов и правой части.
Срез. Получаем Σ{lₚ}(xN)ₚ − s = {xi}, s ≥ 0.
Повтор. Добавляем срез к ограничениям и снова решаем LP симплекс-методом. Повторяем проверку, пока оптимальный план не станет целым.

4. Как программа решает LP-релаксацию

4.1. Две фазы

При равенствах Ax=b начальный базис не всегда виден. Поэтому программа добавляет искусственные переменные.

  • Фаза 1: искусственные переменные должны стать нулевыми. В коде максимизируется их отрицательная сумма.
  • Фаза 2: возвращается настоящая целевая функция.

4.2. Класс Simplex

class Simplex {
    int rowsCount;                         // число строк
    int variableCount;                     // исходные + искусственные
    vector<vector<double>> tableau;       // коэффициенты таблицы
    vector<double> rhs;                    // правые части
    vector<int> basis;                     // базис каждой строки
};

tableau и rhs описывают систему в текущем базисе. Если базис строки — x2, а RHS равен 1.5, то при нулевых небазисных переменных получаем x2=1.5.

4.3. Выбор входящей переменной

optimize вычисляет оценки. Положительная оценка означает, что увеличение переменной может улучшить цель.

int entering = -1;
for (int j = 0; j < enteringLimit; ++j) {
    if (reduced[j] > EPS &&
        (entering == -1 || reduced[j] > reduced[entering] + EPS ||
         (abs(reduced[j] - reduced[entering]) <= EPS && j < entering))) {
        entering = j;
    }
}
if (entering == -1) return true; // найден оптимум

4.4. Выбор выходящей переменной

Минимальное положительное отношение ограничивает рост входящей переменной.

double ratio = rhs[i] / tableau[i][entering];
if (ratio < bestRatio - EPS ||
    (abs(ratio - bestRatio) <= EPS &&
     (leaving == -1 || basis[i] < basis[leaving]))) {
    bestRatio = ratio;
    leaving = i;
}

Если подходящей строки нет, переменную можно увеличивать бесконечно, поэтому LP не ограничена сверху.

4.5. Pivot

void pivot(int row, int column) {
    double value = tableau[row][column];
    for (int j = 0; j < variableCount; ++j)
        tableau[row][j] /= value;
    rhs[row] /= value;
    for (int i = 0; i < rowsCount; ++i) {
        if (i == row) continue;
        double factor = tableau[i][column];
        if (abs(factor) <= EPS) continue;
        for (int j = 0; j < variableCount; ++j)
            tableau[i][j] -= factor * tableau[row][j];
        rhs[i] -= factor * rhs[row];
    }
    basis[row] = column;
}

5. Где что находится в коде

5.1. Дробные части и допуск

const double EPS = 1e-9;
double fractionalPart(double value) {
    double result = value - floor(value);
    return abs(result) <= EPS || abs(1.0 - result) <= EPS
        ? 0.0 : result;
}
bool isInteger(double value) {
    return abs(value - round(value)) <= 1e-7;
}

EPS нужен потому, что double может хранить результат как 0.4999999999 вместо идеального 0.5.

5.2. Результат LP

struct LPSolution {
    SolveStatus status = SolveStatus::Infeasible;
    vector<double> x;
    vector<int> basis;
    vector<vector<double>> rows;
    vector<double> rhs;
    vector<int> nonbasic;
    double value = 0;
};

basis, rows, rhs и nonbasic нужны не только для вывода оптимума, но и для построения среза.

result.x.assign(originalVariables, 0.0);

6. Полный разбор примера

6.1. Результат симплекс-метода

x1 = 1
x2 = 1.5
x3 = 0
x4 = 0
F(x) = 1.5
B = (x1, x2)

x2=1.5 — дробное значение, поэтому нужно строить срез.

6.2. Строка для x2

x2 + 0.25*x3 + 0.25*x4 = 1.5

Дробные части равны 0.25, 0.25 и 0.5.

6.3. Срез Гомори в коде

int fractionalRow = -1;
for (int i = 0; i < (int)result.basis.size(); ++i) {
    if (!isInteger(result.rhs[i])) {
        fractionalRow = i;
        break;
    }
}
int basicVariable = result.basis[fractionalRow];
double rhsFraction = fractionalPart(result.rhs[fractionalRow]);
vector<double> cutCoefficients;
for (int variable : result.nonbasic)
    cutCoefficients.push_back(
        fractionalPart(result.rows[fractionalRow][variable])
    );

7. Как работает полная версия

ДелаетЗачем
Решает LP-релаксацию двумя фазамиНаходит оптимум и печатает симплексные повороты.
Строит срез по строке дробной базисной переменнойУдаляет текущий дробный оптимум, сохраняя целые решения.
Добавляет срез и повторно решает LPПродолжает метод до целочисленного оптимума.
Печатает окончательный планПоказывает решение исходной целочисленной задачи.
Как связано с методичкой: методичка формулирует построение одного среза и останавливается на шаге 11. Полная версия повторяет те же шаги после добавления среза, пока не найдёт целый оптимальный план или не обнаружит несовместность текущей релаксации.
