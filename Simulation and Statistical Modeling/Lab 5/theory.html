0. Задача работы

По двум заданным сетям построить граф достижимости, проверить свойства и сопоставить точные вероятности со статистикой случайных прогонов.

1. Что описывает сеть Петри

Сеть Петри — это рисунок и набор правил для системы, где одни действия должны ждать ресурсы, а другие могут выполняться независимо. Она не считает время и не рисует физическое движение: она отвечает на вопрос «что может произойти дальше, если сейчас фишки стоят вот так?».

ЭлементОбозначениеСмысл
ПозицияКруг, например p1Условие, ресурс или состояние части системы.
ПереходЧерта или прямоугольник, например a или t1Событие, которое меняет состояние системы.
ДугаСтрелкаПоказывает, откуда переход забирает фишки и куда помещает.
Фишка, или маркерТочка внутри позицииНаличие ресурса или выполнение условия. В позиции может быть несколько фишек.
Маркировка MВектор целых неотрицательных чиселПолное состояние сети: количество фишек в каждой позиции.

Цепочка всегда идёт так: позиция → переход → позиция. Прямой стрелки «позиция → позиция» в обычной сети Петри нет. Входящая стрелка говорит «фишка нужна для запуска», исходящая — «после запуска фишка появится здесь».

Что за чёрные «стенки» на рисунке

Чёрный прямоугольник — это переход, а не стенка и не препятствие. Он обозначает событие: например, действие a, b или t1. Когда переход разрешён, он забирает фишки из позиций со входящими стрелками и добавляет фишки в позиции с исходящими стрелками.

Положение прямоугольника — горизонтальное или вертикальное — ничего дополнительно не означает. Важно только, какие стрелки к нему входят и из него выходят. В графе маркировок прямоугольники уже не рисуются: переход показывается названием на стрелке, например M0 --a--> M1.

Пример маркировки: M = [0, 0, 1, 1, 0] означает, что в p3 и p4 находится по одной фишке, а p1, p2 и p5 пусты. Порядок координат всегда p1, p2, …, pn.

Начальная маркировка M0 задаёт состояние до первого события. Модель не описывает время выполнения переходов.

2. Граф достижимости и симуляция

Что показывает граф маркировок

Граф достижимости — результат анализа: вершины обозначают маркировки, стрелки — срабатывания переходов. Marked graph — не этот граф, а класс сети Петри, определяемый её связями. Free-choice — другой структурный класс сети.

Элемент исследованияЧто он означает
ДостижимостьМожно ли попасть из начальной маркировки в заданную.
ТупикМаркировка, в которой нет ни одного разрешённого перехода.
ПараллельностьНесколько переходов могут сработать одновременно, потому что не используют одни и те же фишки.
ОграниченностьМаксимальное число фишек, которое может появиться в позиции.
Класс сетиСтруктурное свойство соединения позиций и переходов.

Зачем нужна симуляция

Сеть не задаёт вероятности выбора переходов. Для численного сравнения в приложении принято допущение: все доступные переходы равновероятны. Теория точно распределяет вероятности по графу, эксперимент оценивает их частотами в N случайных прогонах. Эти методы описаны в разделе «Как считаются теория и опыт».

3. Когда переход может сработать

Переход разрешён, если во всех позициях, откуда в него входят стрелки, есть нужное количество фишек. В наших рисунках вес каждой стрелки равен 1, поэтому для каждой входной стрелки нужна хотя бы одна фишка.

При срабатывании перехода программа делает две операции сразу: сначала забирает входные фишки, затем добавляет выходные. Промежуточного состояния между этими операциями нет.

Разрешённость: M(p) ≥ Pre(p, t) для каждой позиции p.
Новая маркировка: M′ = M − Pre(:, t) + Post(:, t).

Pre(p, t) — сколько фишек переход t должен забрать из позиции p. Post(p, t) — сколько положит обратно. Эти обозначения нужны программе для проверки «можно ли запускать переход» и расчёта новой маркировки.

В первой схеме переход c имеет два входа: p1 и p2. При M = [1, 0, 1, 0, 0] он недоступен: p2 пуста.

При M = [1, 1, 0, 0, 0] переход c разрешён. Он забирает по фишке из p1 и p2 и добавляет по фишке в p3 и p4. Получаем M′ = [0, 0, 1, 1, 0].

Матрица инцидентности

Матрица C = Post − Pre показывает чистое изменение числа фишек. Строка соответствует позиции, столбец — переходу. Отрицательное число означает расход, положительное — появление.

При срабатывании перехода t: M′ = M + C(:, t).

Матрица C описывает результат события, но разрешённость проверяют по Pre. По одному чистому изменению нельзя восстановить, сколько ресурсов требовалось до события.

4. Первая схема: выбор между a и d

В сети 5 позиций, 4 перехода и 10 дуг. Начальная маркировка M0 = [0, 0, 1, 1, 0]. В позиции p4 находится ресурс, за который конкурируют переходы a и d.

Из p4 переходы a и d ведут в разные ветви. a участвует в цикле через c; d переводит фишку в тупиковую позицию p5. Переход b и затем c завершают цикл второй ветви.

ПереходЗабирает фишкиДобавляет фишкиЧто происходит
ap4p1Первая ветвь готовится к синхронизации.
bp3p2Вторая ветвь готовится к синхронизации.
cp1 и p2p3 и p4После готовности обеих ветвей сеть возвращается в начало.
dp4p5Ресурс первой ветви безвозвратно уходит в p5.

Полный граф достижимых маркировок

Вершина графа — целая маркировка сети. Стрелка с подписью перехода показывает одно разрешённое событие. У первой схемы 6 достижимых маркировок и 8 направленных рёбер. Читаем граф слева направо как карту: выбрали переход — перешли по стрелке в новое состояние.

СостояниеM = [p1, p2, p3, p4, p5]Разрешённые события и результат
M0[0, 0, 1, 1, 0]a → M1; b → M2; d → M3.
M1[1, 0, 1, 0, 0]b → M4.
M2[0, 1, 0, 1, 0]a → M4; d → M5.
M3[0, 0, 1, 0, 1]b → M5.
M4[1, 1, 0, 0, 0]c → M0.
M5[0, 1, 0, 0, 1]Нет доступных переходов.

Почему сеть безопасна, но может остановиться

При любом разрешённом событии сохраняются два равенства:

M(p1) + M(p4) + M(p5) = 1.
M(p2) + M(p3) = 1.

Это инварианты позиций: суммы не меняются при срабатывании переходов. Проще говоря, первая фишка всегда находится ровно в одной из p1, p4, p5, а вторая — ровно в одной из p2, p3. Поэтому в одной позиции не может внезапно появиться две фишки. Сеть безопасна, то есть 1-ограниченна, а общее число фишек всегда равно 2.

После d фишка остаётся в p5 навсегда, следовательно, p1 и p4 пусты. Переходы a, c и d больше недоступны. Если b ещё не сработал, он перемещает последнюю фишку из p3 в p2, и сеть попадает в M5. Поэтому сеть неживая, необратимая и имеет достижимый тупик.

Почему автошаг не попадает в p5? Он всегда выбирает первый доступный переход: из M0 получается цикл a → b → c → M0, а d не выбирается. Нажмите d вручную, пока в p4 есть фишка: она уйдёт в p5 навсегда, потому что оттуда нет выходящих дуг. Если в p3 ещё есть фишка, доступен b; после него сеть остановится с фишками в p2 и p5. p5 — позиция сети, а M5 — тупиковая маркировка всей сети. В случайной симуляции d может выбираться наравне с другими доступными переходами.
Пример достижимости: [0, 0, 1, 0, 1] достижима за один шаг d. Маркировка [0, 1, 0, 0, 1] достижима по d → b или b → d. Маркировка [0, 0, 0, 0, 2] недостижима: она нарушает первый инвариант.
Матрица C для первой схемы 
         a   b   c   d
p1       1   0  -1   0
p2       0   1  -1   0
p3       0  -1   1   0
p4      -1   0   1  -1
p5       0   0   0   1

Например, столбец d = [0, 0, 0, −1, 1]: убираем одну фишку из p4 и добавляем одну в p5. Сумма каждого столбца равна нулю, поэтому обычная сумма фишек сохраняется.

5. Вторая схема: разветвление и синхронизация

В сети 6 позиций, 4 перехода и 12 дуг. Начальная маркировка M0 = [1, 0, 0, 0, 0, 1]: по фишке в p1 и p6.

Переход t1 создаёт фишки в p2 и p3. Переходы t2 и t3 могут сработать в любом порядке; после обоих срабатываний t4 возвращает сеть в M0.

ПереходЗабирает фишкиДобавляет фишки
t1p1p2, p3 и p6
t2p2p4
t3p3p5
t4p4, p5 и p6p1
Важная деталь рисунка: p6 уже содержит одну фишку в M0. После t1 в p6 будет две фишки. Переход t4 забирает только одну, поэтому после полного цикла в p6 снова остаётся одна фишка. Накопления с каждым циклом нет.

Полный граф достижимых маркировок

У второй схемы 5 достижимых маркировок и 6 направленных рёбер. Два пути в середине графа отвечают разному порядку срабатывания t2 и t3.

СостояниеM = [p1, p2, p3, p4, p5, p6]Разрешённые события и результат
M0[1, 0, 0, 0, 0, 1]t1 → M1.
M1[0, 1, 1, 0, 0, 2]t2 → M2; t3 → M3.
M2[0, 0, 1, 1, 0, 2]t3 → M4.
M3[0, 1, 0, 0, 1, 2]t2 → M4.
M4[0, 0, 0, 1, 1, 2]t4 → M0.

Почему сеть 2-ограниченна и жива

Для этой схемы сохраняются три равенства:

M(p1) + M(p2) + M(p4) = 1.
M(p1) + M(p3) + M(p5) = 1.
M(p1) + M(p6) = 2.

Из первых двух равенств следует, что в p1…p5 не больше одной фишки. Из третьего — что в p6 не больше двух. Маркировка с двумя фишками в p6 действительно достижима после t1. Поэтому сеть 2-ограниченна, но небезопасна: две фишки в p6 разрешены, а три — невозможны.

Из каждой вершины графа можно вернуться в M0. Значит, какой бы допустимый путь мы ни выбрали, сеть не застрянет навсегда: после завершения ветвей сработает t4 и цикл начнётся снова. Поэтому сеть обратима, жива и не имеет достижимых тупиков.

Обычная сумма фишек меняется: в M0 их 2, после t1 — 4, после t4 — снова 2. При этом существует сохраняющаяся взвешенная сумма:

3M(p1) + M(p2) + M(p3) + M(p4) + M(p5) + M(p6) = 4.

Она получается сложением трёх инвариантов. Поэтому сеть консервативна в смысле положительных весов позиций, хотя простая сумма фишек не сохраняется.

Пример достижимости: [0, 0, 1, 1, 0, 2] достижима по t1 → t2. Маркировка [1, 0, 0, 0, 0, 2] недостижима: сумма M(p1) + M(p6) оказалась бы равной 3 вместо 2.
Матрица C для второй схемы 
        t1  t2  t3  t4
p1      -1   0   0   1
p2       1  -1   0   0
p3       1   0  -1   0
p4       0   1   0  -1
p5       0   0   1  -1
p6       1   0   0  -1

Сумма столбца t1 равна +2, столбца t4 — −2: именно так меняется обычное число фишек. Для полного цикла t1 → t2 → t3 → t4 сумма столбцов равна нулевому вектору.

Живость не означает, что каждый переход разрешён прямо сейчас. Например, во второй схеме в M0 разрешён только t1, но до t2, t3 и t4 можно дойти разрешёнными событиями. Живость — это утверждение о возможности продолжить работу, а не список кнопок, активных в данный момент.

У первой схемы каждый переход может хотя бы однажды сработать из начальной маркировки. Это слабое свойство называют квазиживостью или потенциальной срабатываемостью. Его недостаточно для живости: после попадания в тупик события больше не происходят.

Инварианты и уравнение состояния

Вектор y — инвариант позиций, если yᵀC = 0. Тогда yᵀM = yᵀM0 для любой достижимой маркировки. Именно так обосновываются сохраняющиеся суммы выше.

Если x — вектор количества срабатываний переходов, то для достижимой маркировки выполняется:

M = M0 + Cx, где x содержит целые неотрицательные числа.

Это необходимое условие достижимости в общем случае. Само уравнение не проверяет, можно ли упорядочить события так, чтобы каждое было разрешено в нужный момент. Конкретный допустимый путь в графе служит доказательством достижимости.

Для наших сетей полные графы малы, поэтому нужную маркировку можно непосредственно искать среди всех 6 или 5 состояний.

7. Параллельность и конфликт

Параллельное срабатывание означает, что несколько переходов можно выполнить в один и тот же момент. Для этого нужно, чтобы фишек хватало на весь набор сразу и переходы не забирали одну и ту же единственную фишку.

Для набора S: M(p) ≥ Σt ∈ S Pre(p, t) для каждой позиции p.

Результат совместного шага: из M вычитаются все входные фишки переходов набора и добавляются все выходные. Важно: фишка, которую создал один переход, не может тут же стать входом другого перехода того же совместного шага.

Первая схема

В M0 доступны a, b и d. Переходы a и d конфликтуют: им нужна одна и та же единственная фишка p4. Если сработал один, другой уже не может использовать эту фишку.

  • {a, b} можно выполнить вместе: a расходует p4, b — p3. Результат [1, 1, 0, 0, 0] = M4.
  • {b, d} можно выполнить вместе: ресурсы p3 и p4 различны. Результат [0, 1, 0, 0, 1] = M5.
  • {a, d} выполнить вместе нельзя: для p4 требуются две фишки, а имеется одна.
  • Набор {a, b, d} тоже недопустим из-за нехватки фишек в p4.

Вторая схема

В M0 параллельного набора нет: доступен только t1. После t1 получаем M1 = [0, 1, 1, 0, 0, 2]. Теперь {t2, t3} можно выполнить совместно: t2 расходует p2, а t3 — p3.

M1 → {t2, t3} → M4 = [0, 0, 0, 1, 1, 2].

Последовательности t2 → t3 и t3 → t2 дают такой же результат. t4 разрешается после получения фишек в p4 и p5; вместе с t2 и t3 из M1 он сработать не может, потому что в исходной маркировке его входы ещё пусты.

Два перехода разрешены по отдельности — ещё не значит, что они разрешены совместно. Проверять нужно суммарный расход фишек. Пара a и d в первой схеме — пример этой разницы.

Графы в разделах 3 и 4 построены по одиночным срабатываниям. Если добавить рёбра для совместных шагов, появятся дополнительные стрелки, например M1 → M4 с подписью {t2, t3} во второй схеме. Указанные выше количества рёбер относятся к одиночным событиям.

Сеть свободного выбора

Структурно бесконфликтнаяКаждая позиция имеет не больше одного исходящего перехода.Нет: p4 ведёт к a и d.Да.

Разница: marked graph ограничивает число входящих и исходящих переходов у каждой позиции до одного. Free-choice ограничивает только конфликт: если из позиции можно выбрать несколько переходов, каждый такой переход не должен иметь других входных позиций. Поэтому marked graph всегда free-choice, но обратное неверно.

Итог: схема 1 — free-choice, но не marked graph; схема 2 — и marked graph, и free-choice.

9. Как провести исследование и объяснить результат

Проверка достижимости

Программа строит граф поиском в ширину (BFS): от M0 перебирает разрешённые переходы, добавляет новые маркировки и запоминает предшественников. Поэтому найденный путь содержит минимальное число срабатываний. Если полный граф построен, отсутствие в нём цели доказывает её недостижимость.

Один случайный прогон показывает только один путь и не заменяет полный граф. Правило равновероятного выбора и трактовка строк отчёта приведены в следующем разделе.

10. Как именно считаются теория и эксперимент

Сначала — что можно вычислить по самой сети

Рисунок задаёт строгие правила. Для каждого перехода выписываем, сколько фишек он забирает (Pre) и сколько добавляет (Post). Для данной маркировки M проверяем все входы: фишек должно быть не меньше, чем требует Pre. Если хватает, новая маркировка равна M − Pre + Post.

Повторяем это для всех разрешённых переходов и всех новых маркировок. Получается полный граф достижимости. По нему уже без случайных чисел находим свойства: присутствует ли нужная маркировка, есть ли вершина без выходов (тупик), сколько фишек максимально встречается в каждой позиции, можно ли вернуться в M0. Живость проверяется так: из каждого состояния для каждого перехода должен существовать путь, на котором этот переход снова сможет сработать.

Откуда берутся вероятности: обычная сеть Петри задаёт, что разрешено, но сама по себе не говорит, какой переход выберут. Поэтому проценты в таблице требуют дополнительного правила. В приложении каждый разрешённый переход имеет одинаковый шанс. Если разрешены три перехода — шанс каждого 1/3; если два — 1/2; если один — 1. Все расчёты ниже относятся именно к этому правилу.

Теоретическая колонка: распределяем вероятность по графу

Обозначим число шагов через H. В начале мы точно находимся в M0, поэтому его вероятность равна 1 (100%), а вероятности остальных состояний — 0. Дальше на каждом шаге переносим вероятность по всем разрешённым стрелкам сразу.

Вклад одной стрелки = вероятность исходного состояния ÷ число разрешённых переходов в нём.

Если в одну вершину ведут несколько путей, их вклады складываются. Если у вершины нет выходов, её вероятность остаётся в ней на следующих шагах: прогон уже закончился в тупике. При этом новых срабатываний не прибавляется.

Формальная запись: qk+1(j) = Σi qk(i) · Pij. Здесь qk(i) — вероятность быть в состоянии i после k шагов, Pij — вероятность одного шага из i в j. Для тупика Pii = 1. Если несколько переходов ведут в одну и ту же вершину, их вероятности суммируются. Для наших сетей между каждой такой парой вершин имеется один переход.

Считаем вручную: первая схема, только два шага

  1. До старта: M0 имеет вероятность 1.
  2. Первый шаг: доступны a, b, d. Получаем M1, M2, M3 — каждое с вероятностью 1/3.
  3. Из M1: доступен только b. Вся вероятность 1/3 переходит в M4.
  4. Из M2: доступны a и d. Половина от 1/3, то есть 1/6, идёт в M4; другая 1/6 — в M5.
  5. Из M3: доступен только b. Вся вероятность 1/3 переходит в M5.
Итог после двух шагов: P(M4) = 1/3 + 1/6 = 1/2 = 50%; P(M5) = 1/6 + 1/3 = 1/2 = 50%. У остальных маркировок конечная вероятность 0%. Так как M5 — тупик, теоретическая вероятность тупика равна 50%. Это точный результат, полученный без единого случайного прогона.

Для горизонта 30 шагов приложение повторяет то же распределение вероятностей 30 раз. Вторая сеть считается так же: первый шаг t1 обязателен; на втором выбираем t2 или t3 с вероятностью 1/2. После двух шагов M2 и M3 имеют по 50%, после трёх вся вероятность соберётся в M4, после четырёх — в M0.

Как из вероятностей получаются остальные теоретические строки

ПоказательКак рассчитывается
Конечная маркировкаБерём её вероятность qH после H шагов и умножаем на 100%.
Тупиковый конечный исходСкладываем конечные вероятности всех тупиковых маркировок.
Цель посещалась за прогонСчитаем отдельно вероятность путей, которые ещё не заходили в цель. При входе в цель такой путь перестаёт учитываться в этой группе. В конце берём 1 − вероятность ни разу не попасть в цель. Если цель равна M0, она уже посещена в начале: результат 100%.
Параллельность в концеСкладываем конечные вероятности состояний, в которых ресурсов хватает хотя бы на два перехода вместе. В самом случайном прогоне переходы выполняются по одному.
Среднее число срабатываний перехода tНа каждом шаге для каждого состояния, где t разрешён, прибавляем вероятность этого состояния, делённую на число доступных переходов. Складываем вклады за все H шагов. Тупик ничего не добавляет.
Срабатываний за прогонСкладываем средние числа срабатываний всех переходов. Если тупиков нет, это ровно H. Если прогон может завершиться раньше, среднее может быть меньше H.
Среднее число фишек в позиции pДля каждой конечной маркировки умножаем число её фишек в p на вероятность этой маркировки. Складываем: Σ qH(i) · Mi(p).
Максимум фишек — «граф»Ищем наибольшее число фишек в данной позиции среди всех достижимых маркировок. Это граница для всей сети, даже если до неё нельзя дойти за выбранные H шагов.

Пример среднего: после двух шагов первой схемы с вероятностью 50% получаем M4 = [1,1,0,0,0], а с вероятностью 50% — M5 = [0,1,0,0,1]. Поэтому среднее число фишек в p1 равно 0,5 · 1 + 0,5 · 0 = 0,5. В p2 среднее равно 1, потому что фишка в p2 есть при обоих исходах. Половина фишки в реальном прогоне не появляется: 0,5 — среднее по множеству возможных исходов.

Экспериментальная колонка: действительно запускаем сеть много раз

Обозначим количество прогонов через N. Каждый прогон независимо начинает с M0. Пока не наступил тупик и не сделано H шагов, генератор случайных чисел выбирает один разрешённый переход. Программа применяет правила сети, считает срабатывания и запоминает, заходили ли мы в цель. В конце сохраняет конечную маркировку. Потом начинает следующий прогон с M0.

Опытная вероятность события = число прогонов с этим событием / N.
Для процентов результат умножается на 100%.

Например, сделали 10 000 прогонов по два шага. В 5 037 случаях получили тупик M5. Тогда опытная доля тупиков равна 5 037 / 10 000 = 0,5037 = 50,37%. Теоретическое значение из расчёта выше — 50%. Число 5 037 здесь — пример возможного результата, а не обещание для любого seed.

Экспериментальная величинаКакие счётчики используются
Конечная маркировкаЧисло прогонов, закончившихся в этой маркировке, делится на N.
Тупик, посещение цели, параллельность в концеДля каждого события свой счётчик. Каждый прогон добавляет в него 0 или 1. Счётчик делится на N. Несколько посещений цели в одном прогоне дают одно попадание.
Среднее число срабатыванийОбщее число всех срабатываний за серию делится на N. Для отдельного перехода делится на N его собственный счётчик. Это число срабатываний на прогон, а не доля среди всех событий.
Среднее число фишек в концеСкладываем число фишек в данной позиции в конце каждого прогона и делим сумму на N.
Максимум фишек — «эксперимент»Берём самое большое число, замеченное в этой позиции в начале или на любом шаге любого прогона. Делить на N здесь ничего не нужно.
Как сравнивать правильно: теория и опыт должны использовать одинаковые M0, H, цель и правило выбора переходов. Увеличение N улучшает статистическую оценку, но не гарантирует, что каждый новый результат будет ближе предыдущего. Изменение H меняет сам вопрос — «что будет через другое число шагов» — и поэтому может менять теоретические значения. Одинаковые N, H, цель и seed в этой реализации повторяют ту же серию.

В коде эти две части разделены: PetriExperiment::calculateExact() вычисляет вероятности по графу, а runTrial() и runBatch() выполняют случайные прогоны. Вывод таблицы находится в NetworkPage::runExperiment().
